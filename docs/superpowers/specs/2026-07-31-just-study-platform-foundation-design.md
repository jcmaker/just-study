# just-study 플랫폼 기반 설계

## 상태

2026-07-31 브레인스토밍에서 승인됨.

## 목적

첫 하위 프로젝트는 이후 학습 엔진, Codex MCP, 대시보드가 함께 사용할 최소 플랫폼 기반을 만든다. 이 단계의 결과는 과정 이름과 목표를 입력해 과정 껍데기를 안전하게 생성하고, 재시작 후에도 SQLite와 Markdown이 일치하는 Next.js 애플리케이션이다.

## 범위

- SQLite 연결과 순차 마이그레이션
- 로컬 Markdown 파일 저장
- 과정 생성·목록·조회 서비스
- 최소 입력 화면과 상태 확인 화면
- 과정 생성의 멱등성, 원자적 파일 쓰기, 실패 복구
- 한 개의 서비스 통합 테스트

제외:

- 리서치와 30일 목차
- 일일 강의, 퀴즈, 보충 학습, 회고
- MCP 도구와 Codex 스킬
- 완성형 대시보드
- PDF 업로드, 일정, 과제, 할 일

- 로그인과 다중 사용자

## 기술 접근법

Next.js App Router와 TypeScript를 사용하는 단일 Node 애플리케이션으로 구현한다. 웹 화면, HTTP API, 이후의 MCP 어댑터가 같은 TypeScript 서비스 계층을 사용한다.

Node 22 이상을 지원하고 SQLite 드라이버로 `better-sqlite3`를 사용한다. 현재 지원 환경에서 실험 기능 경고가 발생하는 `node:sqlite`는 영구 저장 기반에 사용하지 않는다. SQL은 작은 저장소 모듈에서 직접 작성하고 ORM은 추가하지 않는다. 파일, UUID, 테스트에는 표준 `node:fs`, `node:crypto`, `node:test`를 사용한다. 별도 API 서버, 상태 관리 라이브러리, 테스트 프레임워크도 추가하지 않는다.

## 실행 구조

```text
Next.js 화면 / HTTP API / 향후 MCP
                 │
                 ▼
           과정 서비스
            ┌────┴────┐
            ▼         ▼
     SQLite 저장소   파일 저장소
```

- 화면과 API는 저장소에 직접 접근하지 않고 과정 서비스만 호출한다.
- 과정 서비스는 입력 검증과 SQLite·파일 작업의 순서를 책임진다.
- SQLite 저장소는 SQL, 마이그레이션, 트랜잭션만 책임진다.
- 파일 저장소는 허용된 `data/` 경로 안의 안전한 읽기·쓰기만 책임진다.
- 이후 MCP도 과정 서비스를 호출하므로 화면과 에이전트의 동작 규칙이 달라지지 않는다.

## 영구 데이터 구조

```text
data/
├── just-study.sqlite
├── just-study.sqlite-wal
├── just-study.sqlite-shm
├── courses/
│   └── <course-id>/
│       └── course.md
└── tmp/
```

SQLite는 WAL 모드와 외래 키 검사를 활성화한다. `data/`는 Git에 포함하지 않는다. 실행 중 안전한 백업은 self-host 완성 단계에서 SQLite 체크포인트와 함께 구현하며, 실행 중인 DB 파일 하나만 임의로 복사하지 않는다.

과정 폴더는 사용자 제목이 아니라 `crypto.randomUUID()`로 만든 과정 ID를 사용한다.

## 데이터 소유권

첫 단계에서 SQLite의 `courses` 행이 과정 존재 여부와 다음 구조화 필드의 기준이다.

- 과정 ID
- 제목
- 목표
- 생성 시각
- 수정 시각
- Markdown 상대 경로
- Markdown 체크섬

`course.md`는 긴 과정 설명을 저장하는 Markdown 기준 파일이다. 제목·목표·ID 같은 구조화 필드는 SQLite에서 생성한 헤더로 표현하며, 이 단계에서는 파일을 직접 수정해 SQLite로 역동기화하지 않는다.

## 최소 사용자 흐름

1. 사용자가 과정 제목과 학습 목표를 입력한다.
2. 서버가 두 필드의 자료형, 공백 제거 후 길이, 빈 값 여부를 검증한다.
3. 클라이언트가 생성한 UUID 요청 ID를 서버가 검증하고 중복 제출을 식별한다.
4. 과정 서비스가 무작위 과정 ID와 임시 폴더를 만든다.
5. 임시 폴더에 `course.md`를 완전히 쓴다.
6. SQLite 트랜잭션을 열고 과정 행을 생성한다.
7. 트랜잭션이 열린 동안 임시 폴더를 최종 과정 폴더로 원자적으로 이동한다.
8. SQLite를 커밋하고 성공한 과정 정보를 목록과 상태 화면에 표시한다.

같은 요청 ID가 다시 들어오면 이미 생성된 같은 과정을 반환한다.

## 입력과 경로 안전

- 공백을 제거한 과정 제목은 1~120자, 학습 목표는 1~2,000자로 제한한다.
- 요청 ID는 UUID 형식만 허용하고 SQLite에서 고유하게 저장한다.
- 저장 경로는 사용자 입력을 이어 붙이지 않는다.
- 모든 파일 경로를 정규화하고 `data/` 아래에 있는지 확인한다.
- 심볼릭 링크를 과정 저장 경로로 따라가지 않는다.
- Markdown 출력에서 사용자 문자열은 구조를 깨뜨리지 않도록 안전하게 처리한다.
- 예상한 도메인 오류만 사용자에게 보여주고 내부 경로와 스택은 노출하지 않는다.

## 오류 처리와 복구

- 임시 파일 쓰기가 실패하면 SQLite 트랜잭션을 시작하지 않는다. 최종 폴더 이동이 실패하면 열린 트랜잭션을 롤백한다.
- SQLite 커밋이 실패하면 성공 응답을 보내지 않고 이미 이동한 최종 폴더를 복구 대상으로 표시한다.
- 프로세스가 비정상 종료되어 임시 폴더가 남으면 시작 시 탐지해 상태 화면에 복구 대상으로 표시한다.
- 최종 과정 폴더처럼 보이는 사용자 자료는 자동 삭제하지 않는다.
- 마이그레이션이 실패하면 읽기·쓰기 기능을 정상인 것처럼 제공하지 않고 상태 화면에 실패를 표시한다.
- `data/`가 쓰기 불가능하면 앱은 과정 생성을 거부하고 정확한 원인을 보여준다.

## 상태 확인

최소 상태 화면과 `/api/health`는 다음을 확인한다.

- 애플리케이션 실행 여부
- SQLite 연결
- 적용된 스키마 버전
- `data/` 디렉터리 읽기·쓰기 가능 여부
- 남아 있는 임시 또는 고아 과정 폴더 존재 여부

응답에는 비밀번호, 토큰, 절대 내부 경로 같은 비밀 또는 환경 정보를 포함하지 않는다.

## 검증

별도 테스트 프레임워크 없이 Node 표준 테스트 실행기로 한 개의 서비스 통합 테스트 파일을 실행한다. 각 사례는 새 임시 `data/` 디렉터리를 사용한다.

다음을 검증한다.

1. 빈 상태에서 SQLite 마이그레이션과 데이터 디렉터리가 생성된다.
2. 과정 하나를 만들면 DB 행과 `course.md`가 각각 하나 생긴다.
3. 같은 요청 ID를 다시 보내도 과정이 중복되지 않는다.
4. 파일 쓰기 실패를 주입하면 DB에 반쪽 과정이 남지 않는다.
5. 서비스를 다시 열어도 생성한 과정이 조회된다.
6. 잘못된 입력과 저장 루트 밖의 경로가 거부된다.
7. 기본 개발·실행 명령이 localhost에만 바인딩된다.
8. 상태 확인이 DB, 스키마, 저장소 상태를 정확히 보고한다.

개발과 실행 스크립트는 Next.js에 `--hostname 127.0.0.1`을 명시한다. 외부 인터페이스 바인딩은 이 단계에서 제공하지 않는다.

## 완료 기준

- 과정 이름과 목표로 과정 껍데기를 안전하게 생성할 수 있다.
- 앱 재시작 후 SQLite와 `course.md`가 일치한다.
- 중복 요청과 저장 실패가 반쪽 데이터를 만들지 않는다.
- 화면과 API가 저장소를 직접 우회하지 않고 과정 서비스를 사용한다.
- 이후 학습 엔진과 MCP가 같은 서비스를 확장해 사용할 수 있다.
