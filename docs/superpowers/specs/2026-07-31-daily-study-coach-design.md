# Daily Study Coach Codex 스킬 설계

## 상태

2026-07-31 브레인스토밍에서 승인됨.

## 목적

`daily-study-coach`는 공부할 주제를 30회 과정으로 구성하고, 하루 45분씩 한 가지 목표를 공부하도록 안내하는 개인용 Codex 스킬이다. 혼자 공부하고 싶지만 방법과 루틴이 없는 학습자를 위해 다음을 제공한다.

- 신뢰도 높은 자료를 폭넓게 조사하고 교차 검증한다.
- 하루에 학습 목표가 하나씩 있는 30일 목차를 만든다.
- 설명, 이해 확인, 퀴즈, 오답 보충으로 매일 학습을 진행한다.
- 쉬거나 대화를 바꾸더라도 정확한 Day와 단계에서 재개한다.
- 실제 학습 내용과 사용자 회고를 읽기 좋은 Markdown으로 남긴다.

여기서 30일은 달력상의 연속 30일이 아니라 순서대로 완료하는 30회의 학습이다. 하루를 쉬더라도 학습을 건너뛰거나 다음날 두 개를 합치지 않는다.

## MVP 범위

MVP는 Codex만 지원하고 모든 과정 데이터를 Markdown 파일로 저장한다. Notion, Claude, 알림, 예약 실행, 데이터베이스, 서버, 다중 사용자 기능은 포함하지 않는다.

30일치 강의를 처음부터 모두 작성하지 않는다. 과정 생성 시 전체 지식 지도를 조사하고, 매일 학습을 시작할 때 오늘 주제만 다시 깊게 조사한다.

## 사용 방법

스킬 호출 이름은 `$daily-study-coach`로 확정한다.

- 새 과정: 스킬을 호출하면서 공부할 주제를 말한다.
- 이어하기: 스킬을 호출하면서 `계속`이라고 말한다.
- 작업공간에 과정이 여러 개면 재개할 과정을 선택하게 한다.
- 같은 주제의 과정이 이미 있으면 기존 과정을 이어갈지 별도 과정을 만들지 묻는다.

## 구조

설치 가능한 Codex 스킬 하나가 전체 학습 흐름을 관리한다. 별도 서비스나 저장용 프로그램은 만들지 않는다.

과정마다 현재 작업공간 아래에 세 파일을 둔다.

```text
study/<주제>/
├── course.md
├── progress.md
└── journal.md
```

### `course.md`

변하지 않거나 천천히 바뀌는 과정 정보를 저장한다.

- 주제와 생성일
- 시작 인터뷰 답변
- 승인된 30일 목차
- 리서치 질문과 주제별 자료 선정 조건
- 자료별 점수, 순위, 선정 이유, 근거의 한계

### `progress.md`

다시 시작하는 데 필요한 최소 상태를 저장한다.

- 현재 Day
- 현재 학습 단계와 마지막 체크포인트
- 이해를 확인한 개념과 보충이 필요한 개념
- 진행 중인 퀴즈, 받은 답변, 시도 횟수
- 마지막 수정 시각

학습 단계는 다음 다섯 가지다.

```text
강의 → 퀴즈 → 보충 학습 → 회고 → Day 완료
```

5문제를 모두 맞히고 회고까지 작성해야 다음 Day로 이동한다. Day 30에서 이 조건을 충족하면 Day 31로 이동하지 않고 과정을 `완료`로 표시한다.

### `journal.md`

완료한 Day마다 읽기 좋은 학습 기록을 추가한다.

- Day 제목과 학습 목표
- 정확한 설명, ELI5 설명, 비유, 구체적인 예제
- 사용자 적용 또는 실습
- 이해한 개념과 보충한 개념
- 퀴즈 결과
- 사용자가 직접 작성한 회고
- 당일 선정 자료와 순위

가독성을 위해 문장을 다듬을 수 있지만 사용자가 말하지 않은 의견, 감정, 사실을 만들어내지 않는다.

## 과정 생성

### 시작 인터뷰

리서치 전에 세 가지를 짧게 묻는다.

1. 이 주제에 관해 이미 아는 내용이나 경험은 무엇인가?
2. Day 30을 마친 뒤 구체적으로 무엇을 할 수 있기를 원하는가?
3. 예제, 이론, 직접 실습 중 어떤 학습 방식을 선호하는가?

모든 과정은 30일 고정이며 하루 학습 목표 시간은 45분이다.

### 2단계 리서치

과정 생성 시 전체 리서치로 다음을 파악한다.

- 주제의 범위와 핵심 개념
- 선수 지식과 개념 사이의 의존 관계
- 가장 효과적인 학습 순서
- 흔한 오해와 실패 지점
- 기초 자료의 품질 순위

결과물은 지식 지도와 30일 목차다. 30일치 강의 원고를 미리 만들지는 않는다. 각 Day를 시작할 때 해당 목표에 필요한 최신 자료를 다시 조사한다.

### 리서치 절차

검색 전에 다음을 먼저 기록한다.

1. 리서치가 답해야 할 질문
2. 고정된 자료 평가 루브릭
3. 주제에 따른 추가 선정 조건

프로그래밍 주제라면 공식 문서와 실행 가능한 예제를, 의학 주제라면 가이드라인과 체계적 문헌고찰을 우선하는 식으로 추가 조건을 정한다.

그다음 다음 순서로 조사한다.

1. 1차 자료, 공식 자료, 신뢰할 수 있는 교육 자료를 폭넓게 수집한다.
2. 검색 전에 정한 루브릭으로 각 후보를 채점한다.
3. 학습 결과에 큰 영향을 주는 주장은 독립적인 고득점 자료 두 개 이상으로 교차 확인한다.
4. 가장 좋은 자료를 점수순으로 선정한다.
5. 자료 사이의 충돌, 불확실성, 근거 부족을 기록한다.

리서치 깊이는 임의의 자료 개수가 아니라 핵심 영역을 빠짐없이 다뤘는지와 주요 주장을 교차 검증했는지로 판단한다.

### 자료 평가 루브릭

| 평가 기준 | 배점 |
|---|---:|
| 저자·기관의 권위와 근거 수준 | 25 |
| 독립 자료와의 교차 검증 결과 | 25 |
| 사용자 목표와 현재 학습 단계의 적합성 | 20 |
| 설명력, 예제, 실습 등 교육 품질 | 15 |
| 최신성과 유지관리 상태 | 10 |
| 무료 접근성과 사용 편의성 | 5 |
| **합계** | **100** |

기본적으로 80점 이상인 자료만 점수순으로 선정한다. 선정 자료마다 한 줄 근거를 남긴다.

80점 이상인 자료가 충분하지 않으면 기준을 몰래 낮추지 않는다. 가장 나은 자료를 사용해야 한다면 점수와 한계를 명시한다. 자료가 충돌하면 양쪽 주장, 근거의 강도, 현재 더 우세한 결론을 함께 설명한다.

### 목차 승인

각 Day에는 하나의 명확한 학습 목표만 둔다. 전체 30일 목차를 사용자에게 보여주고 승인받은 뒤 `course.md`에 저장하고 Day 1을 시작한다.

## 하루 학습 흐름

45분은 학습 속도를 조절하기 위한 목표 시간이다. Codex가 실제 경과 시간을 정확히 측정한다고 가정하지 않는다.

### 1. 회상 — 약 5분

전날의 가장 중요한 개념을 사용자가 직접 떠올린다. Day 1에는 시작 인터뷰에서 파악한 관련 선수 지식을 활성화한다.

### 2. 강의 — 약 20분

오늘의 목표를 가르치기 전에 같은 루브릭과 교차 검증 원칙으로 해당 주제를 심화 조사한다.

핵심 개념은 다음 순서로 설명한다.

1. 정확한 설명
2. 다섯 살 아이도 이해할 수 있는 ELI5 설명
3. 비유
4. 구체적으로 풀어낸 예제
5. 사용자 적용

ELI5와 비유는 이해의 입구로 사용하되 정확한 용어, 중요한 조건, 예외를 생략하지 않는다.

### 3. 인터뷰와 적용 — 약 10분

강의를 작은 단위로 나누고 중간마다 짧은 질문이나 실습을 진행한다. 사용자가 자기 말로 설명하거나 직접 적용하게 하고, 답변에 따라 다음 설명을 조정한다. 핵심 오해를 발견하면 바로잡은 뒤 다음 내용으로 넘어간다.

### 4. 퀴즈와 회고 — 약 10분

암기성 잡학이 아니라 오늘의 목표를 설명하고 적용하는 능력을 확인하는 문제 5개를 낸다. 답변을 보기 전에 채점 기준을 정한다.

- 명확한 5/5이면 회고 단계로 이동한다.
- 서술형 답변의 의미가 애매하면 바로 틀렸다고 하지 않고 추가 설명을 요청한다.
- 하나라도 틀리면 보충 학습 단계로 이동한다.

보충 학습에서는 틀린 개념을 찾아 다른 설명과 새로운 예제로 다시 알려준다. 그다음 이전 문제를 반복하지 않고 새로운 5문제를 낸다. 새 문제도 5/5를 받아야 한다.

보충 학습 때문에 45분을 넘길 것 같으면 사용자가 계속할지, 체크포인트를 저장하고 같은 Day를 나중에 이어갈지 선택할 수 있다.

5/5 이후에는 다음 회고를 작성한다.

1. 오늘 무엇을 배웠는가?
2. 아직 헷갈리는 것은 무엇인가?
3. 오늘 공부에 대한 한 줄 소감은 무엇인가?

세 답변을 받은 뒤에만 `journal.md`를 작성하고 `progress.md`를 다음 Day로 진행한다.

## 저장과 복구

다음 시점에 상태를 저장한다.

- 목차 승인
- 퀴즈 채점
- 사용자가 학습 도중 중단
- Day 완료

파일 쓰기에 실패하면 저장했다고 말하지 않고 어떤 내용이 저장되지 않았는지 알린다.

`progress.md`가 없거나 형식이 손상되면 기존 파일을 보존한다. `journal.md`의 완료 기록으로 복구 상태를 제안하고 사용자 확인을 받은 뒤에만 새 상태를 기록한다. 확인 없이 진도를 진행하지 않는다.

## 오류 처리

- **웹 리서치 불가:** 새 조사를 수행했다고 꾸미지 않는다. 기존에 승인된 자료로 진행할지 학습을 멈출지 묻는다.
- **80점 이상 자료 없음:** 가장 좋은 자료의 점수와 한계를 표시한다.
- **자료 사이의 충돌:** 서로 다른 주장, 근거 강도, 남은 불확실성을 보여준다.
- **사용자 답변이 애매함:** 오답 판정 전에 추가 설명을 요청한다.
- **학습 중단:** 처음부터 다시 시작하거나 진도를 넘기지 않고 저장된 단계와 퀴즈에서 재개한다.
- **여러 과정 존재:** 파일을 수정하기 전에 재개할 과정을 선택하게 한다.
- **Markdown 저장 실패:** 메모리상의 결과를 저장 완료로 처리하지 않고 실패 사실을 정확히 알린다.

## 검증

별도 테스트 프레임워크 없이 대표 과정 하나를 처음부터 끝까지 실행하는 단일 검증 시나리오를 사용한다.

다음을 확인한다.

1. 시작 인터뷰와 전체 리서치 후 정확히 30개의 학습 목표, 자료 점수표, 세 Markdown 파일이 생성된다.
2. 강의, 퀴즈, 보충 학습 도중 중단해도 각각 올바른 단계에서 재개된다.
3. 4/5이면 Day가 진행되지 않고 해당 개념 보충과 새로운 퀴즈가 제공된다.
4. 5/5여도 회고 전에는 `회고` 단계에 머문다.
5. 5/5와 세 회고 답변을 모두 받으면 정확히 한 Day만 진행된다.
6. 리서치 도구가 없을 때 가짜 출처를 만들지 않는다.
7. `journal.md`가 사용자의 실제 말을 왜곡하거나 감정을 꾸며내지 않는다.
8. Day 30 완료 시 과정 상태가 `완료`가 되고 존재하지 않는 Day 31을 만들지 않는다.

MVP의 성공 기준은 새로운 Codex 대화에서도 올바른 과정, Day, 학습 단계로 복귀하며 5/5와 회고 없이는 진도가 진행되지 않는 것이다.

## 의도적으로 제외하는 기능

- Notion 내보내기
- Claude 호환
- 알림과 달력 예약
- 결석분 자동 보충이나 하루 두 개 학습
- 데이터베이스와 클라우드 동기화
- 백그라운드 리서치
- 30일치 강의 선작성
- 분석 대시보드, 연속 학습 표시, 배지, 게임화

이 기능들은 Markdown 기반의 핵심 학습 루프가 한 과정을 안정적으로 완료한 뒤에만 검토한다.
