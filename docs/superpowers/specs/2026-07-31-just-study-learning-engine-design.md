# just-study 학습 엔진 설계

## 상태

학습 행동은 2026-07-31 브레인스토밍에서 승인됨. 플랫폼 저장 구조 변경을 반영함. 플랫폼 기반 다음 단계에서 구현한다.

## 목적

`just-study` 학습 엔진은 공부할 주제를 30회의 과정으로 구성하고 하루 45분씩 한 가지 목표를 공부하도록 안내한다.

- Codex가 신뢰도 높은 자료를 조사하고 교차 검증한다.
- 하루에 목표가 하나씩 있는 30일 목차를 만든다.
- 설명, 이해 확인, 퀴즈, 오답 보충으로 매일 학습한다.
- 중단하거나 Codex 대화를 바꾸어도 정확한 Day와 단계에서 재개한다.
- 실제 학습 내용과 사용자 회고를 읽기 좋은 Markdown으로 남긴다.

30일은 달력상의 연속 30일이 아니라 순서대로 완료하는 30회의 학습이다. 하루를 쉬더라도 학습을 건너뛰거나 다음날 두 개를 합치지 않는다.

## 플랫폼과의 경계

- 리서치, 강의, 인터뷰, 퀴즈 생성과 보충 설명은 Codex의 `$just-study` 스킬이 수행한다.
- `just-study` 서버는 모델을 호출하지 않고 학습 규칙의 검증과 영구 저장을 담당한다.
- 학습 엔진은 플랫폼의 공통 서비스 계층을 사용한다.
- Codex MCP는 다음 단계에서 이 서비스 계층을 공개하는 어댑터다.
- Claude는 Codex 학습 과정을 완주해 품질을 확인한 뒤 별도 클라이언트로 검토한다.

## 데이터 소유권

구조화 상태와 긴 학습 글의 기준을 분리한다.

### SQLite 기준 데이터

- 과정과 30개 Day의 ID·순서·목표
- 현재 Day와 현재 학습 단계
- 출처 URL, 점수, 순위, 선정 이유
- 이해한 개념과 보충이 필요한 개념
- 퀴즈 시도, 문제 식별자, 답변, 채점 결과
- Markdown 상대 경로와 체크섬
- 과정과 Day의 완료 시각

### Markdown 기준 데이터

과정 폴더에는 다음 사람이 읽을 수 있는 파일을 둔다.

```text
data/courses/<course-id>/
├── course.md
├── progress.md
└── journal.md
```

- `course.md`: 전체 리서치 본문, 지식 지도, 승인된 목차의 읽기 좋은 표현
- `progress.md`: SQLite 현재 상태에서 생성한 읽기 전용 스냅샷
- `journal.md`: 완료한 Day의 강의, ELI5, 비유, 예제, 적용, 사용자 회고

`progress.md`와 Markdown 안의 구조화 표를 입력 데이터로 읽어 SQLite를 바꾸지 않는다. 구조화 상태는 서비스 계층을 통해서만 변경한다.

## 사용 방법

- 새 과정: `$just-study`를 호출하면서 공부할 주제를 말한다.
- 이어하기: `$just-study 계속`이라고 말한다.
- 과정이 여러 개면 서버에서 받은 목록을 보여주고 재개할 과정을 선택하게 한다.
- 같은 주제의 과정이 있으면 기존 과정을 이어갈지 별도 과정을 만들지 묻는다.

## 과정 생성

### 시작 인터뷰

리서치 전에 세 가지를 짧게 묻는다.

1. 이 주제에 관해 이미 아는 내용이나 경험은 무엇인가?
2. Day 30을 마친 뒤 구체적으로 무엇을 할 수 있기를 원하는가?
3. 예제, 이론, 직접 실습 중 어떤 학습 방식을 선호하는가?

모든 과정은 30일 고정이며 하루 학습 목표 시간은 45분이다.

### 2단계 리서치

과정 생성 시 전체 리서치로 다음을 파악한다.

- 주제의 범위와 핵심 개념
- 선수 지식과 개념 사이의 관계
- 가장 효과적인 학습 순서
- 흔한 오해와 실패 지점
- 기초 자료의 품질 순위

결과물은 지식 지도와 30일 목차다. 30일치 강의 원고를 미리 만들지 않는다. 각 Day를 시작할 때 해당 목표에 필요한 최신 자료를 다시 조사한다.

### 리서치 절차

검색 전에 다음을 기록한다.

1. 리서치가 답해야 할 질문
2. 고정된 자료 평가 루브릭
3. 주제별 추가 선정 조건

프로그래밍은 공식 문서와 실행 가능한 예제를, 의학은 가이드라인과 체계적 문헌고찰을 우선하는 식으로 주제별 조건을 정한다.

그다음 다음 순서로 조사한다.

1. 1차 자료, 공식 자료, 신뢰할 수 있는 교육 자료를 수집한다.
2. 미리 정한 루브릭으로 후보를 채점한다.
3. 학습 결과에 큰 영향을 주는 주장을 독립적인 고득점 자료 두 개 이상으로 확인한다.
4. 가장 좋은 자료를 점수순으로 선정한다.
5. 충돌, 불확실성, 근거 부족을 기록한다.

리서치 깊이는 자료 개수가 아니라 핵심 영역의 포괄성과 주요 주장의 교차 검증 여부로 판단한다.

### 자료 평가 루브릭

| 평가 기준 | 배점 |
|---|---:|
| 저자·기관의 권위와 근거 수준 | 25 |
| 독립 자료와의 교차 검증 결과 | 25 |
| 사용자 목표와 현재 학습 단계의 적합성 | 20 |
| 설명력, 예제, 실습 등 교육 품질 | 15 |
| 최신성과 유지관리 상태 | 10 |
| 무료 접근성과 사용 편의성 | 5 |
| **합계** | **100** |

기본적으로 80점 이상인 자료만 점수순으로 선정하고 한 줄 근거를 남긴다.

80점 이상인 자료가 충분하지 않으면 기준을 몰래 낮추지 않는다. 가장 나은 자료를 사용해야 한다면 점수와 한계를 명시한다. 자료가 충돌하면 양쪽 주장, 근거의 강도, 현재 더 우세한 결론을 설명한다.

### 목차 승인

각 Day에는 하나의 명확한 학습 목표만 둔다. 전체 30일 목차를 사용자에게 보여주고 승인받은 뒤 서비스 계층을 통해 저장하고 Day 1을 시작한다.

## 학습 상태

현재 Day의 상태는 다음 순서로만 이동한다.

```text
강의 → 퀴즈 → 보충 학습 → 회고 → Day 완료
```

- 5문제를 모두 맞히고 회고를 작성해야 다음 Day로 이동한다.
- Day 30에서 조건을 충족하면 Day 31을 만들지 않고 과정을 `완료`로 표시한다.
- 사용자가 중단하면 현재 단계, 진행 중인 퀴즈, 받은 답변을 저장한다.
- 재개 시 처음부터 반복하거나 다음 단계로 추측해 이동하지 않는다.

## 하루 45분 학습 흐름

45분은 속도를 조절하기 위한 목표 시간이며 Codex가 실제 시간을 정확히 측정한다고 가정하지 않는다.

### 1. 회상 — 약 5분

전날의 가장 중요한 개념을 사용자가 직접 떠올린다. Day 1에는 시작 인터뷰에서 파악한 선수 지식을 활성화한다.

### 2. 강의 — 약 20분

오늘 목표를 가르치기 전에 같은 루브릭과 교차 검증 원칙으로 해당 주제를 심화 조사한다.

핵심 개념은 다음 순서로 설명한다.

1. 정확한 설명
2. 다섯 살 아이도 이해할 수 있는 ELI5 설명
3. 비유
4. 구체적으로 풀어낸 예제
5. 사용자 적용

ELI5와 비유는 이해의 입구로 사용하되 정확한 용어, 중요한 조건, 예외를 생략하지 않는다.

### 3. 인터뷰와 적용 — 약 10분

강의를 작은 단위로 나누고 중간마다 질문이나 실습을 진행한다. 사용자가 자기 말로 설명하거나 적용하게 하고 답변에 따라 다음 설명을 조정한다. 핵심 오해를 발견하면 바로잡은 뒤 넘어간다.

### 4. 퀴즈와 회고 — 약 10분

암기성 잡학이 아니라 오늘 목표의 설명과 적용 능력을 확인하는 문제 5개를 낸다. 답변을 보기 전에 채점 기준을 정한다.

- 명확한 5/5이면 회고로 이동한다.
- 서술형 답변이 애매하면 바로 오답 처리하지 않고 설명을 요청한다.
- 하나라도 틀리면 보충 학습으로 이동한다.

보충 학습에서는 틀린 개념을 다른 설명과 새 예제로 다시 알려준다. 이전 문제를 반복하지 않고 새로운 5문제를 내며 새 문제도 5/5를 받아야 한다.

45분을 넘길 것 같으면 계속할지, 체크포인트를 저장하고 같은 Day를 나중에 이어갈지 사용자가 선택한다.

5/5 이후에는 다음 회고를 작성한다.

1. 오늘 무엇을 배웠는가?
2. 아직 헷갈리는 것은 무엇인가?
3. 오늘 공부에 대한 한 줄 소감은 무엇인가?

세 답변을 받은 뒤에만 `journal.md`를 갱신하고 다음 Day로 진행한다.

## 저장 시점

다음 시점에 서비스 계층을 통해 SQLite와 Markdown을 갱신한다.

- 목차 승인
- 퀴즈 채점
- 사용자가 학습 도중 중단
- Day 완료

저장에 실패하면 성공했다고 말하지 않으며 어떤 단계가 저장되지 않았는지 알린다.

## 오류 처리

- **웹 리서치 불가:** 새 조사를 수행했다고 꾸미지 않는다. 승인된 기존 자료로 진행할지 멈출지 묻는다.
- **80점 이상 자료 없음:** 가장 좋은 자료의 점수와 한계를 표시한다.
- **자료 충돌:** 서로 다른 주장, 근거 강도, 남은 불확실성을 보여준다.
- **사용자 답변이 애매함:** 오답 판정 전에 설명을 요청한다.
- **학습 중단:** 저장된 단계와 진행 중인 퀴즈에서 재개한다.
- **SQLite·Markdown 저장 실패:** 성공 상태나 다음 Day를 기록하지 않고 실패를 알린다.
- **상태와 파일 체크섬 불일치:** 자동 덮어쓰지 않고 상태 화면에 복구 필요를 표시한다.

## 검증

대표 과정 하나로 다음을 검증한다.

1. 시작 인터뷰와 전체 리서치 후 정확히 30개의 학습 목표와 자료 점수표가 저장된다.
2. 강의, 퀴즈, 보충 학습 도중 중단해도 각각 올바른 단계에서 재개된다.
3. 4/5이면 Day가 진행되지 않고 해당 개념 보충과 새 퀴즈가 제공된다.
4. 5/5여도 회고 전에는 `회고` 상태에 머문다.
5. 5/5와 세 회고 답변을 모두 받으면 정확히 한 Day만 진행된다.
6. 리서치 도구가 없을 때 가짜 출처를 만들지 않는다.
7. `journal.md`가 사용자의 실제 말을 왜곡하거나 감정을 꾸며내지 않는다.
8. Day 30 완료 시 과정이 `완료`가 되고 Day 31을 만들지 않는다.
9. 새 Codex 대화에서도 서버 상태를 읽어 올바른 과정, Day, 단계로 복귀한다.

## 현재 제외 범위

- Notion 내보내기
- Claude 지원
- 서버 자체의 모델 호출
- 알림과 달력 예약
- 결석분 자동 보충이나 하루 두 개 학습
- 30일치 강의 선작성
- 분석 대시보드, 연속 학습 표시, 배지, 게임화
